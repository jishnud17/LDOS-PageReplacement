DIRECTORY LAYOUT
----------------
Datasets and analysis outputs are grouped by workload:

  data/synthetic_workloads/<workload>/     raw .csv.gz per run
  data/real_workloads/<workload>/
  data/large_local/<workload>/             raw .csv.gz too large for GitHub
                                           (gitignored, local only)
  results/synthetic_workloads/<workload>/  *_reactivity.csv, *_trajectories.csv
  results/real_workloads/<workload>/

  Workload folders: hot_cold, sequential, temporal (synthetic);
  gups_hotset_move, gups_skewed, gapbs_pr_twitter, gapbs_bc_twitter,
  gapbs_cc_kron, xsbench, liblinear (real).

  hot_cold/ holds the SAME workload measured two ways -- *_uffd (phase-1
  userfaultfd: every access counted) and *_pebs (hardware sampling, the
  method real workloads use).  That pair is the measurement control: only
  the instrument differs, so any ranking change between them is an
  artifact of measurement, not of workload.

TOTALS
------
  ~13.8M rows of per-page signal time series across 13 datasets
  (4 synthetic incl. the UFFD/PEBS control pair, 9 real)
  (42 columns each: 10 base + 32 signal components)
  ~180,000 windowed state-change events feeding the reactivity analysis
  6 distinct real workloads from the mentor-provided repo + script:
    gups (hotset-move, skewed), gapbs pr / bc / cc_sv, XSBench, liblinear
  GUPS replicated x2 per variant
  4 hardware platforms: c220g2/g5 (Haswell -- store-attribution only),
  r650 (Ice Lake Platinum 8360Y) and sm110p (Ice Lake Xeon Silver 4314)
  -- load attribution verified working on both Ice Lake parts

  NOTE ON DATA STORAGE: three gzipped datasets exceed GitHub's 100MB file
  limit and are kept locally under data/large_local/<workload>/
  (gitignored): xsbench (405MB), liblinear (305MB), and the gapbs_cc_kron
  -n 10 rerun (160MB).  Their analysis outputs ARE committed under
  results/real_workloads/<workload>/ where they exist, and the exact run
  commands above regenerate the raw data.  The superseded gapbs_cc_kron
  -n 2 dataset was removed (0 events; replaced by the -n 10 rerun).

CONFIGURATION DELTAS vs THE LAB'S run_workload.sh (ARMS harness)
-----------------------------------------------------------------
For comparability discussions: the lab harness runs GUPS at 16 threads /
2^36=64GB table / 2^33=8GB hot set, and PageRank at -i 150 -t 0 with
OMP_NUM_THREADS=16 + numactl -N0, interpose threshold 128MB, under DRAM
capacity budgets.  Our configs are smaller ON PURPOSE: per-page 50ms signal
series require PEBS sample density -- at an 8GB hot set (~2M hot pages),
each hot page is sampled roughly once a minute at our sampling period,
making per-page bars statistically empty.  Scale vs. per-page granularity
is a real trade-off to decide for phase 2.  (Our runs also apply no DRAM
budget: telemetry mode measures signals without capacity pressure.)
